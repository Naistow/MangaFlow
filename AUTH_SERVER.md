# Сервер доступа MangaFlow

Клиент теперь требует серверную авторизацию. Локальная `mangaflow.db` хранит историю
и не разрешает вход. Без `MF_AUTH_SERVER_URL` или при недоступном API вход останавливается
до загрузки OCR/LLM. Не удаляйте старую БД: она нужна для истории и переноса ваших кодов.

## Что подготовлено, а что ещё нужно разместить

В репозитории есть API FastAPI, серверная БД SQLite на постоянном томе, административная
CLI и Docker-конфигурация. Публичный сервер автоматически не создаётся. Домен не обязателен:
подойдёт постоянный HTTPS-адрес, предоставленный хостингом. Для работы других пользователей
нужно разместить этот сервис на доступном им сервере и указать его HTTPS-адрес в клиенте.
Локальный запуск ниже позволяет проверить всё на своём ПК; это не публичное размещение.

Нельзя распространять `server/data/`, `/data/auth.db`, резервные копии, сессионные токены
или существующую `mangaflow.db` вместе с клиентом. Сам адрес API не является секретом.

## Локальная проверка на Windows

Из корня проекта, рабочим Python 3.11+:

```powershell
python -m venv .venv-auth
.\.venv-auth\Scripts\python.exe -m pip install -r server/requirements.txt
```

Чтобы сохранить текущие коды и HWID, **закройте MangaFlow**, сделайте резервную копию
исходной БД и один раз импортируйте записи в ещё пустую серверную базу:

```powershell
.\.venv-auth\Scripts\python.exe -m server.migrate_auth --source mangaflow.db --destination server/data/auth.db
```

Импорт не переносит историю страниц и не перезаписывает заполненную серверную базу.
Вместо импорта можно начать с новых кодов:

```powershell
.\.venv-auth\Scripts\python.exe admin_invites.py generate --count 5
.\.venv-auth\Scripts\python.exe -m uvicorn server.app:create_app --factory --host 127.0.0.1 --port 8000 --no-proxy-headers
```

Для локальной проверки добавьте в `.env` клиента:

```dotenv
MF_AUTH_SERVER_URL=http://127.0.0.1:8000
MF_AUTH_ALLOW_LOCAL_HTTP=1
```

HTTP разрешён только с явным флагом и только для loopback-адресов. При первом входе
после переноса введите существующий логин/инвайт; последующие запуски используют токен,
зашифрованный Windows DPAPI для текущего пользователя в `storage/auth_session.bin`.
Токен связан с сервером и HWID. Копирование этого файла другому пользователю Windows
или на другой ПК не заменяет серверную активацию.

## Docker на сервере

```sh
docker compose up -d --build
docker compose exec auth python admin_invites.py generate --count 5
docker compose exec auth python admin_invites.py users
docker compose exec auth python admin_invites.py requests
docker compose exec auth python admin_invites.py approve 1
docker compose exec auth python admin_invites.py reject 2
docker compose exec auth python admin_invites.py unbind MF-XXXX-XXXX
docker compose exec auth python admin_invites.py delete MF-XXXX-XXXX
```

Сервис слушает `127.0.0.1:8000` хоста, данные живут в томе `auth-data`. Не запускайте
`docker compose down -v`, если хотите сохранить коды и пользователей. Для переноса
старой базы в Docker скопируйте её как исходный файл в контейнер и выполните импорт
в `/data/auth.db` до первого запуска сервиса; не копируйте открытую WAL-базу.

Поставьте перед сервисом TLS reverse proxy либо TLS вашего хостинга и направьте
запросы на порт 8000. Сертификат должен проверяться клиентом; `verify=False` не
используется. В клиенте задайте:

```dotenv
MF_AUTH_SERVER_URL=https://адрес-вашего-сервиса
```

`MF_AUTH_ALLOW_LOCAL_HTTP` для публичного сервера не нужен. Удалите его из публичной
конфигурации. Reverse proxy должен ограничивать размер тела до 8 KiB и частоту
запросов по реальному IP. Приложение также ограничивает тело и попытки активации;
оно не доверяет произвольному `X-Forwarded-For`. Без настройки доверенного proxy
все посетители за ним имеют общий IP для внутреннего лимита — настройте ограничение
на proxy и соответствующий лимит приложения для вашего размещения.

Административных HTTP-методов нет: коды выпускаются только через CLI на сервере.
Обновления кода клиента или локальный `admin_invites.py` на чужом ПК не добавляют
инвайты в вашу серверную базу. Настройте резервное копирование постоянного тома.

## Доступ и отзыв сессии

API: `POST /v1/activate`, `POST /v1/session`, `POST /v1/reset-requests`, `GET /health`.
Токены случайные, на сервере хранятся только SHA-256-хеши. Сессия действует 7 суток;
затем потребуется повторный вход с тем же кодом. Перепривязка/отвязка/удаление
инвайта аннулируют прежние токены. Проверка выполняется при запуске, перед экранным
переводом и во время пакетной обработки в рабочих потоках; успешный ответ API
кэшируется максимум на 60 секунд. Уже выполняющийся запрос модели не прерывается
посреди генерации, но следующий контроль доступа запрещает дальнейшую обработку.
При сетевой ошибке повторная проверка не подменяется локальной авторизацией.

Логин/код и хеш HWID отправляются только вашему API; изображения и переводы туда
не отправляются. История сохраняется локально с привязкой к серверному пользователю.

## Ограничение открытого клиента

Обычный клиент больше не принимает самостоятельно созданные локальные инвайты.
Однако обладатель полного Python-кода может удалить проверку или направить изменённый
клиент на собственный сервер. Пока OCR и перевод полностью локальны, нельзя гарантировать
защиту от такой модификации. Сервер централизует действительные активации, заявки,
отзыв и защиту от повторного использования кода на вашем API; он не делает открытый
клиент невзламываемым. Для обязательного контроля над самой функцией часть функции
должна требовать серверный ресурс — это уже меняет архитектуру локального перевода.
