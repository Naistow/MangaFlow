# Инвайты и пакетный перевод

Доступ перенесён на отдельный API. Локальная `mangaflow.db` теперь хранит историю,
но не разрешает вход. Сначала настройте сервер и `MF_AUTH_SERVER_URL` по инструкции
[AUTH_SERVER.md](AUTH_SERVER.md). Без сервера приложение остановится до загрузки моделей.
Домен для локальной проверки не требуется; публичное размещение сервера ещё нужно выполнить.

Команды ниже выполняются **на вашем сервере** из корня проекта:

```powershell
python admin_invites.py generate --count 5
python admin_invites.py invites
python admin_invites.py users
python admin_invites.py requests
python admin_invites.py approve 1
python admin_invites.py reject 2
python admin_invites.py unbind MF-XXXX-XXXX
python admin_invites.py delete MF-XXXX-XXXX
python main.py
```

`--db PATH` указывается перед подкомандой. По умолчанию используется
`server/data/auth.db` либо путь из `MF_AUTH_DB`.
Логин закрепляется за инвайтом при первой активации. `unbind` снимает HWID,
сохраняя логин и историю; следующий вход с теми же реквизитами привяжет новый ПК.
`delete` отзывает код, сохраняя пользователя и его историю.
После одобрения заявки старый HWID теряет автоматический вход, новый получает его.
Старые серверные токены отзываются. Клиент перепроверяет доступ максимум через
60 секунд при следующем контрольном пункте обработки.

HWID — SHA-256 от Windows MachineGuid и SMBIOS UUID (Win32_ComputerSystemProduct).
Без доступных идентификаторов вход останавливается; случайные подстановки не используются.
База содержит хеш HWID, а не исходные аппаратные идентификаторы.

## Серверная модель доступа

Инвайты, привязки HWID, заявки и хеши токенов хранятся в серверной SQLite.
Клиент обращается к HTTPS API, хранит только DPAPI-защищённый токен и локальную
историю. Локального fallback при недоступном сервере нет. Перенос старых кодов,
Docker, команды администратора и ограничения открытого клиента описаны в AUTH_SERVER.md.

## Кабинет и результаты

ПКМ по трею → «Личный кабинет / Пакетный перевод». Укажите название,
выберите изображения или папку и запустите перевод. Файлы папки сортируются
по числам в именах; выбранные вручную страницы идут в порядке диалога.
Вложенные папки не обходятся. Исходники не изменяются.

Один QThread последовательно обрабатывает страницы существующими экземплярами
OCR и переводчика: дополнительные модели и параллельные GPU-задания не создаются.
Одновременный экранный перевод блокируется до окончания пакета. Ollama и модель
из `.env` не заменяются. Все запросы используют один ограниченный контекст 1024
токена, чтобы вместить до четырёх реплик и избежать смены конфигурации runner
между обычным переводом, группой и сокращением. По сравнению с прежними 512
токенами размер KV-кэша может вырасти; запросы остаются строго последовательными.
Абсолютная гарантия расхода менее 6 GB зависит от модели и других процессов.
Пакетный детектор дополняет экранную эвристику поиском замкнутых светлых баблов,
включая короткие реплики. Столбцы одного замкнутого облачка объединяются в один
OCR-кроп. Экранный детектор и его настройки не меняются.

Весь OCR страницы выполняется из неизменяемого исходного кадра до первой зачистки.
Новый пакетный метод `recognize_page_bubble` добавляет запас 20 px вокруг символов
и белый паддинг 24 px, ограничивая размер входа модели. Пустые кропы отбрасываются
до вызова Manga-OCR; реплики из одной каны и знаков не отбрасываются по длине.
Переводчик отправляет до 4 реплик одним JSON-запросом, ограничивая также суммарную
длину входных реплик 200 символами. Последняя группа может быть короче. Результаты
сопоставляются по уникальным id; при неверном формате выполняется перевод по одной
реплике, а группировка для этой пары URL/модель отключается до перезапуска приложения.
Одиночные реплики используют прежний промпт с примером. Сетевые ошибки не кэшируются
и не вызывают каскад дополнительных повторов группы.

Пакетная отрисовка очищает только маску небольших тёмных компонентов букв через
локальный CPU-inpaint. Замкнутая светлая внутренность бабла определяется отдельно;
контур, крупные внешние штрихи и компоненты, касающиеся края области поиска, защищаются
с отступом 5 px. При незамкнутом контуре используется консервативная внутренняя область
детекторной рамки. Перевод наносится прозрачным слоем без белого прямоугольника
и дополнительной обводки. На сложном фоне или при слипшихся буквах часть исходных
штрихов может сохраниться: алгоритм предпочитает защитить рисунок. Если безопасную
область найти нельзя, этот бабл остаётся в оригинале, остальные обрабатываются.
Страница и пакет получают статус `partial`; координаты пропусков, причины и
текст перевода доступны в истории и в `translation_warnings.txt` внутри ZIP.
Слипшиеся столбцы букв, полностью находящиеся внутри защищённой внутренности,
не считаются рамкой только из-за их размера. Для незамкнутого контура это разрешено
только на преимущественно белом фоне. Соседний бабл не выбирается по небольшому
пересечению с текущей рамкой. Повторные OCR-фрагменты одного облачка объединяются
до перевода вместо потери второй реплики из-за пересечения при отрисовке.

Для верстки проверяется несколько безопасных прямоугольников внутри защищённой
области: более широкий и короткий вариант может вместить целые русские слова,
которые не входят в самый большой по площади узкий прямоугольник. Выбирается
вариант с наибольшим читаемым шрифтом; все его пиксели остаются внутри защищённой
маски. Только если ни один вариант не подошёл, запрашивается сокращение реплики.
Перевод измеряется и рисуется только Pillow,
независимо от DPI экрана: шрифт 11–18 px, перенос только между целыми словами,
центрирование по фактическим метрикам блока. Длинные слова не разрезаются по буквам,
знаки препинания остаются с предшествующим словом. Если перевод при 11 px не
помещается, пакетный режим запрашивает у той же Ollama-модели более краткую
формулировку с сохранением смысла (до двух попыток). Если она тоже не помещается
или Ollama недоступна, бабл сохраняется в оригинале с предупреждением; текст не сжимается
в нечитаемую картинку. Ошибки чтения/сохранения изображения по-прежнему означают
ошибку страницы. Отмена обработки не перехватывается как предупреждение.

Окна входа и кабинета используют общую тему `ui/theme.py`: тёмный индиго/фиолетовый
фон #151426 / #1E1D35 / #272542, мягкие лавандовые акценты и округлые панели.
Слева находится навигация, сверху — Activated и управление окном, справа —
реальная статистика готовых томов/страниц и история. Раздел «История» показывает
подробности выбранного пакета и ошибки отдельных страниц; «Профиль» — реквизиты.
Тема применяется только к этим окнам и не меняет экранный оверлей.
Кабинет открывается без белого системного заголовка. Перетаскивание за верхнюю
строку, двойной щелчок для разворачивания, изменение размера за края/нижний правый
угол и кнопки сворачивания/разворачивания/закрытия работают внутри тёмного окна.

Результаты: `storage/batch_ID/` (PNG) и `storage/batch_ID.zip`.
История хранит страницы, ошибки и статусы `pending`, `processing`, `completed`,
`partial`, `failed`, `cancelled`. ZIP частичного пакета содержит только успешные
страницы. Кнопка «Скачать ZIP» копирует архив в выбранное место.
Удаление записи удаляет историю пакета и его страниц, оставляя файлы на диске.
Закрытие кабинета скрывает окно; перевод продолжается. Выход через трей ожидает
текущую операцию OCR/Ollama и завершает пакет со статусом `cancelled`.
После аварийного завершения незаконченные пакеты отмечаются как `failed`
при следующем входе пользователя. Одновременный запуск двух экземпляров приложения
блокируется, чтобы не загружать вторую копию моделей в VRAM.

Проверки без загрузки реальных моделей:

```powershell
python -m unittest discover -s tests -v
```

Для API-тестов дополнительно установите `server/requirements.txt` и `httpx`.

## Ускорение обоих режимов

Экранный и пакетный перевод используют один OCR и один переводчик. Ограниченные
LRU-кэши процесса хранят только строки и хеши: 512 результатов OCR по точным пикселям
подготовленного кропа, 1024 перевода и 256 сокращённых реплик. Кадры и тензоры в кэше
не сохраняются. Изменение изображения, URL, имени модели или словаря не использует
старый результат. После перезапуска приложения кэши пусты.

HTTP Session переиспользует соединение; дополнительные GPU-модели и параллельные
LLM-запросы не запускаются. OCR работает в eval/inference mode без изменения
точности весов. Шрифты переиспользуются без изменения метрик. Маски символов строятся
через таблицы меток вместо полного просмотра кадра для каждого компонента; варианты
безопасной области вычисляются за один проход гистограмм, а не заново для каждой ширины.
В консоли выводятся длительности этапов и число запросов/новых реплик для сравнения
с реальной скоростью на вашем компьютере.

Контрольный замер на исходной странице (медиана трёх запусков CPU-части без OCR/LLM):
детекция + очистка + варианты областей — 1.204 s до оптимизации и 0.321 s после.
Совпали все координаты, безопасные маски и очищенные пиксели.
Для четырёх реплик на работающей `gemma2:9b` с одинаковым контекстом 1024 токена:
четыре одиночных запроса — 9.527 s, один групповой — 6.926 s. Повторный вызов
для тех же реплик не обращается к модели. Это локальные контрольные замеры,
а не гарантия ускорения каждой страницы; длина реплик, холодная загрузка модели
и нагрузка на GPU/CPU влияют на результат.

## Если выложить проект на GitHub

В обычном клиенте принимаются только коды вашего настроенного API. Запуск чужой
копии `admin_invites.py` не меняет вашу серверную БД; заявки передаются на сервер.
Сам сервер необходимо разместить отдельно — GitHub не является сервером авторизации.
Владелец полного исходного кода может изменить клиент или удалить проверку, поэтому
абсолютной защиты локальной функции открытый клиент не даёт. Подробности — AUTH_SERVER.md.

`.gitignore` исключает `.env`, `mangaflow.db*`, `storage/`, кэши и `venv/` из новых
добавлений. Он не удаляет уже отслеживаемые файлы или данные из истории Git.
